# Reproducible Synthea raw data

This stage replaces the unparameterized official sample with a reproducible
Synthea release for ExMed-BERT integration and loading tests. It invokes
upstream Synthea rather than fabricating disconnected healthcare rows with
Faker.

The generated and published development evidence is recorded in
[RESULTS.md](RESULTS.md).

## Pinned cohort

- Synthea: `v4.0.0`
- Executable SHA-256: `ed43c20ad40ba5c3bc724503a5af032715fe3c491620b766148e7c2361e6ecc1`
- Population target: 10,000 living patients; Synthea can also retain simulated
  patients who died before the reference date
- Population and clinician seeds: `201214`
- Reference date: `2025-01-01`
- Geography: Massachusetts
- History: complete (`exporter.years_of_history=0`)
- Output: patients, encounters, conditions, medications, and procedures CSV
- Threads: one, to keep output row ordering stable

Synthea's `-p` option targets living patients. Consequently `patients.csv` can
contain slightly more than 10,000 rows when deceased simulated patients are
retained; the manifest records living, deceased, and total counts separately.

The release is a software and scaling fixture. It is not evidence that a model
is clinically useful, unbiased, or ready for patient care.

## Generate

Synthea v4 requires Java 17 or newer. The generator downloads the official JAR,
verifies its upstream checksum, runs into a fresh staging directory, checks all
patient and encounter relationships, and writes `provenance.json` last.

```bash
python generate.py \
  --output /tmp/synthea-v4.0.0-p10000-seed201214-ref20250101 \
  --jar-cache /tmp/exmedbert-tools/synthea-v4.0.0.jar
```

The output path is immutable: generation fails if it already exists. A smaller
smoke cohort can be generated by setting `--population 100`, but its destination
must use a different version name.

## Publish

The approved development destination is:

```text
/Volumes/shyam_internal_ssa_catalog/deep_learning/exmedbert_air/synthea/raw/
  synthea-v4.0.0-p10000-seed201214-ref20250101
```

Publish only to a new version path:

```bash
python publish.py \
  --source /tmp/synthea-v4.0.0-p10000-seed201214-ref20250101 \
  --destination /Volumes/shyam_internal_ssa_catalog/deep_learning/exmedbert_air/synthea/raw/synthea-v4.0.0-p10000-seed201214-ref20250101 \
  --profile fevm-default
```

CSV files are uploaded first and `provenance.json` last. A directory lacking
that marker is incomplete and must not be consumed.

If publication completed but the client was interrupted before its final size
check, validate the existing path without writing:

```bash
python publish.py --validate-only \
  --source /tmp/synthea-v4.0.0-p10000-seed201214-ref20250101 \
  --destination /Volumes/shyam_internal_ssa_catalog/deep_learning/exmedbert_air/synthea/raw/synthea-v4.0.0-p10000-seed201214-ref20250101 \
  --profile fevm-default
```

## Prepare the ExMed-BERT snapshot

The existing serverless Spark job consumes this raw release without receiving
or passing a Spark DataFrame to AIR:

```bash
databricks bundle run prepare_exmedbert_snapshot -t dev \
  -- \
  --source-root /Volumes/shyam_internal_ssa_catalog/deep_learning/exmedbert_air/synthea/raw/synthea-v4.0.0-p10000-seed201214-ref20250101 \
  --output-root /Volumes/shyam_internal_ssa_catalog/deep_learning/exmedbert_air/exmedbert/snapshots \
  --snapshot-version synthea-v4-p10000-v1 \
  --num-shards 16 \
  --max-oov-fraction 0.05
```

Do not overwrite the existing official sample or any prior raw/snapshot
version.
